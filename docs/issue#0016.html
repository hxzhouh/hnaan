Implementation Notes

Issue #16 — Restore company maps with the supplied browser AK — 2026-11-17

Design Decisions

Configure either runtime through the same port

Supply BAIDU_MAP_AK through the Config interface for both Workers and Node. Actions reads the repository Secret at deployment; no live key is committed. Browser use necessarily sends the browser AK to the SDK. Keep company coordinates in the existing baiduxy configuration and preserve the original map areas, company contact details and navigation links.

Translate metadata and interpolate safely

Reuse the current UI dictionary and CMS overrides for English company details. Serialize metadata as escaped JSON and build information-window nodes with textContent so content cannot break out of a script or execute HTML.

Deviations

The previous release intentionally disabled embedded maps because the old AK raised a blocking authorization alert. The user has now provided a replacement browser AK; only configured contact/resource pages load the SDK. This implements the restoration follow-up from Issue #14.

Tradeoffs

Maintain the existing site's canvas-based JSAPI 3.0 integration instead of introducing a WebGL or provider migration. Loading is asynchronous and a 20-second deadline retains contact guidance on SDK or render stalls. Review found that synchronous map construction is insufficient proof of rendering: the timeout now remains active until tilesloaded, and late SDK/render callbacks cannot replace an already displayed fallback.

Keep mobile map attribution visible

Actual mobile screenshots found that the legacy contact wrapper was only 239px tall while the embedded map was 350px; overflow hid the bottom controls and attribution. Let the wrapper derive its height from the existing map. The browser checks now assert that no clipping ancestor hides the map.

Open Questions

No implementation decision awaits confirmation. Future AK rotation, quota, enabled services and permitted Referer domains remain controlled by the user's Baidu account; address changes can use the existing site configuration. The new AK works for hnaan.cn, but actual workers.dev testing returned a Referer authorization error. BAIDU_MAP_HOSTS limits SDK loading to explicitly authorized hosts (default: SITE_URL hostname); alias domains retain the fallback. Additional hosts require both provider authorization and deployment configuration. The website does not bypass provider authorization or mute its alerts. Basemap lettering is provided by Baidu; the site's company information is localized separately.
